## 배치 A — 발표 엔진(미리보기·직원 보기·내려받은 파일 공통)

### A0 🐞 큰 덱에서 미리보기가 빈 화면 (원장 그림 image 1·2)
- 원인: 발표 화면 `.app`은 grid인데 열 크기를 안 정해 둠 → 317장이면 아래 점(dot) 317개(약 5,400px)가 열 폭을 키움 → 흰 발표판(가운데 정렬)이 화면 오른쪽 밖으로 밀림. 그림에서 오른쪽 위 「전체화면·사용법」 단추와 아래 「›」 단추가 안 보이는 것이 증거. 직원 보기(`hubShowViewer`)·발표 파일 만들기 결과도 같은 엔진이라 같이 깨짐.
- 고침: `SLIDE_CSS`의 `.app`에 `grid-template-columns:minmax(0,1fr)`, `.controls`·`.center`가 줄어들 수 있게(`min-width:0`). 엔진 `buildControls`는 장이 30장을 넘으면 점을 만들지 않음(아래 「84 / 317」 숫자만).
- 검증: 시험 — 30장 넘는 덱에서 점 0개·30장 이하에서는 장 수만큼. 브라우저 — 317장짜리 덱 미리보기에서 흰 발표판이 iframe 안에 보임.

### A3 글 상자끼리 자동으로 안 겹치게 (image.png: 「아니라고」가 「배치 물품」을 덮음)
- `phGeoSrc`에 순수 함수 `phAvoid(fixed, movable, bnd, gap)` 추가. 사각형은 `{x,y,w,h}`(왼쪽 위 기준, px).
  - `fixed` = 움직이지 않는 장애물(가져온 글 상자 = `m.w != null`인 label — PPT에서 원래 자리라 옮기지 않음).
  - `movable` = 순서대로 자리 잡는 것(화살표 글 + 편집기에서 넣은 글 `m.w == null`).
  - 각 movable: 이미 놓인 것(fixed + 앞서 놓인 movable)과 `gap`(4px) 넘게 겹치지 않으면 그대로. 겹치면 후보 자리 = 겹친 상자 각각의 바로 아래·위·오른쪽·왼쪽(gap 띄움) → `bnd` 안이고 아무것과도 안 겹치는 후보 중 원래 자리에서 가장 가까운 것. 없으면 원래 자리.
  - 돌려주는 값: movable과 같은 순서의 새 `{x,y}` 배열. 결정적(같은 입력 → 같은 출력).
- 발표 엔진 `phLayout`: 모든 글의 크기·자리를 먼저 잰 뒤 `phAvoid`로 고치고 transform 적용. 단계(step)와 상관없이 모든 글을 함께 계산(새 글이 나올 때 기존 글이 튀지 않게).
- 편집 화면 `peRedraw`: 같은 함수로 같은 결과. 단, 지금 끌고 있는 글(`PE.drag`의 대상)은 계산에서 빼고 손가락 자리 그대로.
- 시험: 겹친 두 글 → 뒤 글이 비켜남 · 안 겹치면 그대로 · 고정 글은 안 움직임 · 경계 밖 후보는 안 고름 · 결정적.

### A4 PPT 같은 등장 효과
- 표시마다 `fx`(선택): 화살표 `''`(기본 = 그려지듯) · `'fade'`(나타나기). 글 `''`(기본 = 미끄러지듯) · `'fade'`(나타나기) · `'zoom'`(확대) · `'pop'`(튀어오르기).
- `phNormalize`: 허용 값이 아니면 `fx` 지움. 엔진: 해당 클래스(`fx-fade` 등)를 붙이고 CSS로 효과. `prefers-reduced-motion`이면 전부 투명도만.

### A9a 글 줄바꿈·배경색 (그리기 쪽)
- 글 상자 `white-space:pre-line`(발표 `.ph-lbl-box`, 편집 `.pe-lbl`). 운영 덱 1,358개 글 중 줄바꿈 든 글 0개(10-11 확인) → 기존 화면 안 바뀜.
- 글 `bg`(배경색, `phSafeColor` 통과한 것만) 적용. `phNormalize`는 `color`·`bg`가 안전한 색이 아니면 지움.

### A7 발표 파일 만들기 = 사진·효과 그대로
- 이미 엔진·사진(데이터주소로 담음)이 들어감 — A0 고치면 큰 덱도 보임. 보탬: 사진을 담는 동안 「사진 담는 중 n/전체」 알림, 못 담은 사진이 있으면 「사진 N장을 못 담았어요」 알림(조용히 넘어가지 않게).

## 배치 B1 — 편집 화면 조작

### B1 사진 붙여넣기(Ctrl+V)
- `paste` 이벤트: 클립보드에 그림 파일이 있을 때만. 글 입력 칸에서 글(text/plain)도 함께 있으면 기본 동작(글 붙여넣기)에 맡김.
- 지금 장이 사진 없는 사진 슬라이드 → 그 장에 넣음. 그 밖(사진 있는 장·다른 종류) → 지금 장 바로 뒤에 새 사진 슬라이드를 만들어 넣음(기존 사진은 안 덮음).
- 사진 고르기(`fi.onchange`)와 같은 함수로 묶어 같은 화면 갱신·같은 경쟁 처리(`attachPhoto`).

### B2 장 번호 쳐서 이동
- 슬라이드 칸 머리에 숫자 칸(「장 이동」) — 번호 + Enter → `pickSlide(n-1)`. 범위 밖이면 알림.

### B5 왼쪽·오른쪽 이름표
- 가운데 머리: 「편집 — 여기서 고쳐요」. 오른쪽 머리: 「미리보기 — 직원에게 이렇게 보여요」.

### B9b 글 편집: 줄바꿈·글자색·배경색·크기·효과
- 사진 위 글 입력(`peOpenPop`)을 여러 줄 칸으로: Enter = 확정, Shift+Enter = 줄바꿈(한글 조합 중 Enter 무시 유지).
- 표시 목록 줄: 글 칸을 여러 줄 칸으로. 줄마다 꾸미기: 글이면 글자색·배경색(`input type=color`)·크기(기본/조금 크게 20/크게 28/아주 크게 40 — `size`, pt)·효과, 화살표면 화살표 색·효과. 「기본으로」 하나로 색·크기·효과를 지움. 바꿀 때마다 `snap()` 한 번.

### B12 화살표 여러 번 꺾기
- R(꺾기) = 고른 화살표의 가장 긴 구간 가운데에 꺾임점 하나 더(최대 점 8개, 넘으면 알림). Shift+R = 곧게 펴기(처음·끝 점만). 꺾임점(처음·끝 아닌 손잡이) 더블클릭 = 그 점 빼기.
- 가운데 손잡이 모양(`.mid`)을 처음·끝을 뺀 모든 점에. 도구 막대에 「펴기 Shift+R」 단추.
- 꺾임점 넣기·빼기는 순수 함수(`phBendAdd(pts)`·`phBendRemove(pts,i)`)로 시험.

### B14 불러오기 안내
- 불러오기 단추 `title`: 「발표 파일 만들기로 만든 .html 또는 .json만 열려요」.

### B15 순서 기본 0(바로 보임)
- 새 화살표·글의 `step` 기본 0. 표시 목록 순서 칸: 0이면 비워 두고 자리표시 「바로」(비우면 0). 편집 화면 번호 배지는 순서가 1 이상일 때만.
- 안내 문구: 「순서: 비우면 바로 나옴 · 숫자 = 클릭 몇 번째에 나올지」. `phNextStep`이 안 쓰이게 되면 지움(시험도 정리).

## 배치 B2 — 편집 칸 크게 + 확대·이동(원장 ①안)

### B10 편집 칸 크게
- 미리보기 칸 접기/펴기 단추(접으면 편집 칸이 그만큼 넓어짐). 접힘 여부는 이 브라우저에만 기억(localStorage, 읽기·쓰기 모두 try/catch).
- 사진 편집 판 크기: 높이 상한을 화면 높이에 맞춰 키움(지금 58vh → 보이는 칸 높이 기준).

### B13 확대·이동(편집 화면만)
- 사진 판을 바깥 틀(`pe-view`, 넘침 숨김) 안에 넣고 판에 `translate+scale`. 확대 1~6배.
- 확대: 도구 막대 「＋」「－」「맞춤」 + Ctrl+휠(마우스 자리 기준). 이동: 확대 중 선택(A) 도구로 빈 곳 끌기 · Space 누른 채 끌기 · 가운데 단추 끌기.
- 좌표: `pePct`는 그대로(getBoundingClientRect가 확대를 반영). `peXY`는 확대 전 px로 바꿔(`(clientX-r.left)*PE.W/r.width`) `peHit` 거리 계산이 맞게.
- 다른 장으로 가면 확대는 1배로.

## 배치 C — 허브 자동 저장 + 설명서

### C6 허브 자동 저장(노션처럼)
- 허브 편집 모드에서 고칠 때마다(`markDirty`) 2.5초 뒤 `hubSave({auto:true})`. 공개·비공개 상관없이.
- 막는 조건: 보기 모드·편집 권한 없음·충돌 상태(`HUB.conflict`)·사진 올리기 실패 남음(상태 줄 「사진 실패 — 자동 저장 멈춤」). 저장 중이면 끝난 뒤 아직 「저장 안 됨」이면 다시 예약.
- 자동 저장은 성공 알림을 띄우지 않고 상태 줄만(「저장됨 · 자동」). 실패는 상태 줄 「자동 저장 실패 — 저장 단추를 눌러 주세요」 + 다음 고침 때 다시 시도(끝없이 재시도 안 함). 충돌은 기존 `hubConflict` 그대로.
- 허브에서 「불러오기」는 덱을 통째로 바꾸고 바로 자동 저장되므로, 열기 전에 확인 창.
- 공개 칸 옆 안내(마우스 올리면 보이는 title): 「고치면 자동 저장돼요. 공개 중이면 저장된 내용을 다음에 여는 직원부터 볼 수 있어요. 이미 열린 화면은 새로고침이 필요해요.」 — 허브 보기는 열 때 서버에서 다시 읽고(`hubBoot`) 열린 화면은 자동 갱신 안 됨(1차 대화 Sol high 지적 반영).
