# 통합 근무명부·부서별 캘린더 설계

## 목적

- 종이 월간표에 수기로 다시 적지 않아도 직원 허브의 근무표 입력이 월간 캘린더에 자동 반영되게 한다.
- 로그인 계정이 있는 직원과 로그인하지 않는 의사를 하나의 근무명부에서 관리한다.
- 날짜별로 `Dr.`, `진료실`, `데스크`, `기공실`의 근무 인원과 이름, 야간, OFF, 연차를 확인한다.
- 테스트·공용 계정은 삭제하지 않고 관리자 설정으로 근무표와 집계에서 제외한다.

## 확인된 현재 상태

- `profiles`에는 직원 계정이 있지만 현재 `dept`가 모두 비어 있다.
- `schedules`에는 147건의 근무 데이터가 있고 2026-07-27부터 2026-10-12 주차까지 존재한다.
- 현재 캘린더는 승인 연차와 `off`만 근무표에서 가져오며 `work`, `evening`, `etc`는 표시하지 않는다.
- 현재 근무 주차는 모두 `초안` 상태다.
- `abc`, `테스트`, `공용1`은 활성 계정이며 일부는 기존 근무 데이터도 갖고 있다.

## 결정

- 통합형 B안을 채택한다. 근무표의 기준 식별자를 로그인 계정 UUID가 아니라 통합 근무명부의 `person_id`로 바꾼다.
- 계정 보유 여부와 근무명부 포함 여부를 분리한다. 로그인 계정은 유지하면서도 근무표·캘린더·인원 집계에서 제외할 수 있다.
- 직급을 `원장`, `부원장`으로 나누지 않고 의료진 그룹을 `Dr.`로 통일한다.
- 이름과 부서는 코드에 하드코딩하지 않는다. 원장 화면에서 추가·변경·비활성화한다.
- 퇴사자는 삭제하지 않고 비활성화하여 과거 일정과 집계를 보존한다.
- 공휴일은 정보 태그로만 표시한다. 공휴일이라는 이유로 `OFF` 또는 치과 휴무로 자동 판정하지 않는다.

## 데이터 모델

### `schedule_people`

통합 근무명부의 정본이다.

- `id uuid primary key default gen_random_uuid()`
- `profile_user_id uuid null unique references profiles(user_id)`: 로그인 계정이 있으면 연결한다.
- `name text not null`: 표시 이름의 원본이다. `Dr.` 접두사는 화면에서 부서에 따라 붙인다.
- `department text not null`: `Dr.`, `진료실`, `데스크`, `기공실`, `미지정` 중 하나다.
- `included_in_schedule boolean not null default true`: 꺼지면 근무표·캘린더·인원 집계에서 제외한다.
- `active boolean not null default true`: 퇴사 시 false로 바꾸고 과거 기록은 유지한다.
- `sort_order integer not null default 0`
- `created_at`, `updated_at`

### `schedules`

- `person_id uuid`를 추가하여 `schedule_people(id)`를 참조한다.
- 기존 147건은 `schedules.user_id -> schedule_people.profile_user_id` 대응으로 `person_id`를 백필한다.
- 새 고유키는 `(week_start, person_id, day)`로 한다.
- 기존 `user_id`는 비로그인 근무자 일정을 위해 nullable로 바꾸고 첫 배포에서 롤백용으로 유지하지만, 앱의 읽기·쓰기는 `person_id`를 사용한다.
- 이관 검증과 운영 확인이 끝난 뒤 별도 후속 마이그레이션에서 `user_id` 제거 여부를 결정한다.

## 초기 이관

1. 모든 `profiles` 행에 대응하는 `schedule_people` 행을 만든다.
2. 기존 `schedules` 147건에 `person_id`를 채운다.
3. 백필 전후 실행 시점 총행수(현재 실측 147건), 주차별·직원별·시프트별 건수를 비교한다. 불일치하면 제약 변경을 중단한다.
4. `abc`, `테스트`, `공용1`의 `included_in_schedule`을 false로 설정한다. 계정과 기존 기록은 삭제하지 않는다.
5. 기존 계정 `정용태`의 부서를 `Dr.`로 지정한다.
6. 비로그인 명부에 `정도경`, `정규민`을 `Dr.`로 추가한다. 중복 이름이 있으면 새 행을 만들지 않고 관리자 확인 대상으로 남긴다.
7. 나머지 직원은 `미지정`으로 두며 관리자가 원장 화면에서 실제 부서를 선택한다. 이름만 보고 부서를 추정하지 않는다.

## 권한

- 로그인한 직원은 통합 근무명부와 공표된 근무표를 조회할 수 있다.
- 기존 근무표 초안 작성 권한은 유지한다.
- 원장·실장·매니저만 비로그인 근무자 추가, 부서 변경, 집계 포함 여부 변경, 비활성화를 할 수 있다.
- 근무표 공표 권한은 현재 규칙을 유지한다.
- RLS는 로그인 여부만 확인하는 정책으로 넓히지 않고, 명부 관리 작업에는 역할 검사를 적용한다.

## 원장 화면

- 기존 직원 권한 관리 표에 `근무부서`, `근무표·집계 포함` 열을 추가한다.
- 부서는 `Dr.`, `진료실`, `데스크`, `기공실`, `미지정`에서 선택한다.
- `비로그인 근무명부` 영역에서 이름과 부서를 추가한다.
- 행별로 `재직`, `퇴사` 상태를 바꿀 수 있다. 퇴사는 확인 후 비활성화하며 과거 데이터는 지우지 않는다.
- `abc`, `테스트`, `공용1`은 최초부터 `근무표·집계 제외`로 보인다.

## 근무표 화면

- 행의 정본을 `schedule_people`로 바꾼다.
- 부서 순서는 `Dr.`, `진료실`, `데스크`, `기공실`, `미지정`이다.
- 로그인 직원과 비로그인 의료진을 같은 표에서 편집한다.
- 제외 또는 비활성 상태인 사람은 새 주차 입력표에서 숨긴다.
- 과거 주차를 볼 때는 당시 일정이 있는 비활성 근무자를 계속 표시한다.
- 시프트는 기존 `근무`, `OFF`, `야간`, `기타`를 유지한다.

## 캘린더 화면

- 기존 월간 7열 달력 형식을 유지하되 날짜 셀의 정보 높이를 늘린다.
- 날짜별 표시 순서는 다음과 같다.
  1. 공휴일·관리자 이벤트
  2. `Dr. n명 · 이름들`
  3. `진료실 n명 · 이름들`
  4. `데스크 n명 · 이름들`
  5. `기공실 n명 · 이름들`
  6. `야간 · 이름들`
  7. `연차 · 이름들`
  8. `OFF · 이름들`
- `근무`와 `야간`은 해당 부서 근무 인원에 포함한다. `야간`은 별도 줄에도 한 번 더 표시한다.
- `OFF`와 승인 연차는 부서 근무 인원에서 제외한다.
- `기타`는 인원 집계에서 제외하고 `기타 · 이름들`로 별도 표시한다.
- 해당 주차가 초안이면 날짜 셀에 `작성 중` 표시를 붙이고, 공표된 주차는 `확정`으로 표시한다.
- 공휴일 태그는 근무 입력과 독립적이다. 공휴일에도 근무자가 있으면 정상적으로 부서별 근무자를 표시한다.
- 모바일에서는 날짜를 누르면 그날의 전체 명단을 펼쳐 보이게 하고 월간 격자에는 인원수 중심으로 축약한다.

## 오류 처리

- 통합 명부 또는 일정 조회 실패 시 빈 캘린더로 오인하지 않도록 `근무표를 불러오지 못했습니다`를 표시한다.
- 부서 미지정 근무자는 `미지정` 그룹에 표시해 누락을 숨기지 않는다.
- 중복 이름은 허용할 수 있으므로 내부 식별은 항상 `person_id`를 사용한다.
- 저장 실패 시 기존 자동 저장 상태 영역을 오류 상태로 바꾸고 성공으로 표시하지 않는다.

## 검증

- 마이그레이션 전후 실행 시점의 `schedules` 총행수(현재 실측 147건)와 주차별·시프트별 집계가 동일해야 한다.
- 기존 계정 일정과 비로그인 의사 일정이 같은 주차에서 함께 저장·조회되는지 확인한다.
- 집계 제외를 켠 계정이 근무표·캘린더·부서 인원수에서 빠지고 로그인은 유지되는지 확인한다.
- 비활성화한 사람이 새 주차에서 숨고 과거 일정에서는 유지되는지 확인한다.
- 공휴일에 `근무`가 입력된 경우 공휴일과 근무자 모두 표시되는지 확인한다.
- 초안·공표 상태가 월 경계와 주차 경계에서도 정확히 표시되는지 확인한다.
- 데스크톱과 모바일에서 이름이 셀 밖으로 넘치지 않고 키보드로 주요 조작이 가능한지 확인한다.

## 롤백

- 첫 배포에서는 기존 `schedules.user_id`를 유지한다.
- 새 화면에 문제가 생기면 코드만 이전 `user_id` 조회 방식으로 되돌릴 수 있다.
- 새 `person_id`와 `schedule_people`은 기존 행을 삭제하지 않으므로 데이터 손실 없이 재시도할 수 있다.

## 제외 범위

- 종이 근무표 이미지의 필기 내용을 OCR로 옮기지 않는다.
- 공휴일을 치과 휴무로 자동 변환하지 않는다.
- 출퇴근 기록과 급여 계산 규칙 자체는 이번 범위에서 바꾸지 않는다. 기존 근무표 연결이 끊기지 않는지만 검증한다.
