# 카드 지출 점검 화면 구현 메모

원장 전용 메뉴 안에 「지출 점검」을 추가했음. 기간·카드·용도로 거래를 고르고 월별·카드별·가맹점별 합계를 볼 수 있음. 취소는 음수로 합산하며 원화 미환산 건을 따로 표시했음. SpendUi가 쓰는 SpendCycle 계산 부품을 기간 합계에 재사용했음.

가맹점 사전의 표시 이름·용도·AI 이름·메모를 원장이 고칠 수 있음. 기본 용도가 기타인 가맹점을 「처음 보는 가맹점」에 표시했음. 사전 전체는 검색으로 찾을 수 있음. 표시 건수를 넘으면 안내를 표시하고 검색·기간 축소로 찾아볼 수 있음.

정기결제 검토표 v2의 61행을 app_settings의 ledger.subscriptions로 옮길 SQL을 만들었음. 원장 확인 KB의 ImagineArt·미리캔버스 해지와 나노바나나 유지 결정을 함께 반영했음. 화면에서 기존 항목 편집과 새 항목 추가가 가능함. 조회한 설정값이 그대로 있을 때만 갱신하여 다른 화면의 편집을 덮어쓰지 않음. 저장 실패 시 입력을 유지했음.

성공 거래는 원문을 읽지 않음. 실패 문자는 원장에게만 만료 전 건을 보여 주고 펼쳐 읽을 수 있게 했음. 기존 실패 표의 원장 읽기 정책을 추가할 SQL을 준비했으며 운영에는 실행하지 않았음. 월 대조는 안내 자리만 만들었고 실제 업로드·대조·세무 출력은 다음 단계임. 즉시·주간 알림도 다음 단계임.

화면 글은 hub_ui_texts, 카드·용도·카드사 목록과 표시 기준은 app_settings를 사용함. 새 설정 정의는 기존 허브 설정에 뒤로 추가되므로 기존 편집칸 순서를 유지했음. 기본값 SQL은 재실행해도 원장이 고친 값을 덮어쓰지 않음.

## 운영 반영 전제

운영 반영은 별도 「운영 올려」 지시 뒤임. 1단계 card_ledger_v1.sql, 2단계 card_ledger_ui_v2.sql, 1단계 웹훅, hr.html·hub-texts.js·card-ledger-ui.js를 함께 반영해야 함. 새 표나 정기결제 설정을 읽을 수 없으면 화면에 읽기 실패를 표시하며 임의 목록을 저장하지 않음. 하나카드 표본은 보류 상태임.

## 검증과 저장소

증거는 초인종 5f0d8ee1의 work/completion-evidence.json과 각 시험 로그에 있음. Node 전체, Deno 전체, 1단계 SQL, 화면 SQL, 합성 DB를 연결한 실제 Chromium 화면을 실행했음. 실제 폰·운영 DB·운영 웹훅은 이번에 실행하지 않았음.

Deno는 1단계와 같은 오프라인 캐시에서 Supabase 2.57.4 시험용 별칭을 사용했음. 운영 의존성 2.110.9 빌드는 이번에도 미확인임. 웹훅 핵심 시험은 별칭 없이도 별도로 확인함.

공용 main은 오래된 718f5a6이고 원격 main 캐시는 fc87efb였음. 최신 원격 캐시 fc87efb까지 fast-forward하여 웹훅 v12 수정과 1단계를 함께 포함했음. 외부 Git fetch·push는 하지 않았음.

작업 워크트리의 .git은 이번 work/repo.git의 독립 저장소를 가리킴. 독립 Git 기록·커밋·bundle은 work 안에만 있음. 초기 .git 연결 변경 실패 뒤 명령이 계속되어 공용 저장소에서 이 작업 브랜치를 75d2830에서 fc87efb로 fast-forward한 일이 1회 있었음. 그때 해당 워크트리 Git 메타데이터도 변경되었음. 이후에는 독립 저장소로 연결했고 공용 기록을 더 수정하지 않았음. 공용 main·다른 브랜치·다른 워크트리 본문은 수정하지 않았음. 범위 예외를 숨기지 않고 A검토요청에 남겼음.

되돌릴 때는 독립 저장소의 화면 구현 커밋을 되돌리면 됨. .git 연결 원본은 work/original-git-pointer.txt에 백업되어 있으나 공용 워크트리 기록과의 재연결은 맡긴 대화가 잠금 범위를 확보한 뒤 처리해야 함. 이번 일꾼은 잠금 밖 기록을 다시 수정하지 않음.
