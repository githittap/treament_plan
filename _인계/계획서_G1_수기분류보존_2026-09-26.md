# 계획서 — T8 G1 수기 분류 보존 수정

## 목표

`db/employee_job_groups.sql`이 확정 실명과 같은 기존 미연결 `schedule_people` 행의 `department` 수기 분류를 `job_group` 확정값으로 덮거나, 고유 profile과 연결해 화면 분류를 바꾸는 결함을 고친다. `department`가 NULL·공백·`미지정`인 행만 자동 분류 대상으로 남긴다.

## 범위와 금지

- 수정 대상: `db/employee_job_groups.sql`, `tests/sql/pglite-employee-job-groups.mjs`.
- 테스트는 `department`가 NULL/공백/`미지정`인 확정 roster는 지정 그룹을 받고, 다른 기존 수기 분류인 미연결 roster는 department·job_group·profile 연결이 그대로 남음을 확인한다.
- 고유 exact-name profile의 정상 연결, Dr. 제외, 기존 중복 방지·재실행 보존 동작을 유지한다.
- profile/Auth나 중복 roster를 새로 만들지 않는다.
- 운영 DB·Storage·Edge·Cafe24·main push·배포·실기기 확인은 범위 밖이다.
- 시험은 요청된 PGlite와 schedule-roster 한 번, `git diff --check` 한 번이다.
- 결과 기록은 기존 `구현결과.md` 및 연결된 BUSD 행에 로컬 커밋/미배포 상태 한 줄을 추가한다. 요구추적표는 변경 요구 판정이 확실히 달라질 때만 갱신한다.

## 순서

1. 테스트 픽스처에 재현 케이스를 추가해 현재 SQL에서 실패함을 확인한다.
2. 자동 분류·profile 연결 조건을 미지정 상태에만 한정하도록 SQL을 최소 수정한다.
3. 지정된 PGlite 및 schedule-roster 시험을 각 한 번 실행하고 결과를 기록한다.
4. diff 점검 후 허용 파일만 명시적으로 stage하고 한국어 로컬 커밋을 만든다.
5. `구현결과.md`와 같은 BUSD task에 완료 증거와 미배포 경계를 남긴다.
