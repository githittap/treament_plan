# Z⑤-03 보안서약 PDF 서명 — 로컬 범위 판정 계획

## 기준과 승인

- 기준 요청: `P1_요청_2026-09-26.md` 및 `구현지시서.md`의 `Z⑤-03` 원문 “보안서약서 PDF를 업로드하고 자동 서명하게”.
- 원장 확정으로 전달된 동선: 직원 보관 서명을 자동 불러옴, 직원이 계약별 내용을 읽고 확인함, 통합 계약의 근로계약·의료정보 보안·개인정보 취급자 세 구역에 각각 서명함.
- 범위: G1 로컬 코드·시험·기록만. 운영 DB/Storage/Edge, secret, main push, 실제 직원 서명·전송은 금지.

## 읽기 전 대조에서 확인한 상태

- `hr.html`의 통합 계약은 대기 계약에서 보관 서명을 자동 불러오고, 세 구역 각각의 내용 확인 체크와 서명이 있어야 완료 버튼이 열림.
- 통합 계약 PDF는 직원이 원본 확인 뒤 세 구역별 페이지·좌표를 입력하고 `contract-pdf-sign`으로 세 서명이 반영된 완료 PDF를 생성함. 완료 전 서버의 별도 확인 RPC를 거침.
- 일반 `employee_documents` 업로드는 PDF를 보관할 뿐 서명 파이프라인에 연결하지 않음.
- 현재 `onboardingEvidenceComplete`는 서명이 없는 `보안서약서` 파일 업로드도 보안서약 체크를 충족한 것으로 판단함. 이는 체크 충족일 뿐 서명이 아니며 `Z⑤-03` 충족으로 보지 않음.
- SQL은 employee_documents MIME을 PDF/JPEG/PNG로 제한하지만 프런트 검증은 DOCX/HWP 등도 허용함. 이번 Z⑤-03 판정 범위 밖으로 두고 고치지 않음.
- MIME 차이가 DB insert 오류로 나타나면 이미 업로드한 Storage object가 남을 가능성이 있음. 이번 범위에서는 수정하지 않음.
- 기존 통합 계약 PDF 기능이 별도 보안서약 PDF 요구를 충족하는지, 일반 서류함에서 올린 PDF를 통합 계약과 어떻게 연결할지에 대한 승인된 매핑을 찾지 못했음.
- 계약 PDF 서명 위치는 직원이 직접 페이지와 좌표를 입력하며 Edge는 페이지 경계만 검증함. 승인 템플릿 좌표로 고정되기 전에는 별도 PDF 자동 서명 완료로 판정하지 않음.

## 실행 계획

1. `employee_documents` 업로드 및 계약 PDF 서명 경로의 자료 모델·기존 시험을 대조함.
2. 원장 확정 동선이 이미 구현된 구간과 별도 PDF 경로의 차이를 결과 기록·요구추적표에 구분해 기록함.
3. 요구추적표와 구현결과 모두 `Z⑤-03=부분(미완료·결정 대기)`로 명시함. 다음 결정을 한 목록으로 기록함: ①서명 대상은 일반 서류함의 독립 PDF인지 계약 PDF 원본인지 ②직원 직접 업로드 PDF도 미서명 상태로 체크리스트 완료 처리할지 ③서명 시점·템플릿/좌표는 무엇인지 ④완료 PDF를 어디에 보관할지. 현재 계약 PDF 위치 입력 주체는 직원임을 적음.
4. 별도 PDF와 통합 계약을 연결하는 구현 설계는 매핑이 확정되기 전까지 코드 변경하지 않음. 두 관련 시험은 Worktree root에서 현 HEAD 기준 증거용으로 한 번 실행하고, 추가 반복 실행은 하지 않음.
